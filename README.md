# PXE 装机台

跑在一台 x86_64 移动小主机上的 Linux 装机设备。小主机插上自己的装机网口，给目标服务器提供 DHCP、TFTP 和启动菜单。

- 菜单里自选 Ubuntu、Debian、Rocky Linux 或 AlmaLinux，按配置无人值守安装。
- 按服务器表装机：机器从网卡启动后按序列号对上表格里的一行，超时后自动安装。
- 表里没有的机器、已经装好的机器，菜单超时后从本地硬盘启动，避免误装机。要重装时在服务器列表里点「重装」。

管理口不要接到装机交换机上。DHCP 只监听配置里的装机网口。

## 项目和服务器表

总览只查看当前状态。新建项目时只建立目录。安装设置、DHCP 和服务器表写在项目里面。

打开一个项目的开关后，装机使用这一套临时地址池和安装菜单。同时只能启用一个项目。没有打开的项目时，不分配装机地址。DHCP 地址池要和这台小主机某一块网口在同一个子网。多块网口时，不必跟打开控制台的那个地址相同。DNS 和 VLAN 可以不填。

项目开始时上传一张服务器表，一行一台机器。列是：序列号、IPMI MAC、原用户、原密码、目标用户、目标密码、IPMI 地址、掩码、路由、IPMI VLAN、安装系统、系统地址、定制需求。VLAN 和系统地址可以留空。系统地址是装好后系统的 IP，批量任务优先用它登录。安装系统要和该项目里某条安装设置的名称一致。定制需求会附加到那台机器的安装后脚本。

上传并且项目开关打开之后，小主机用 DHCP 租约按 IPMI MAC 找到 BMC，按表里的地址、掩码、路由和 VLAN 写入 IPMI 网络，再把用户和密码改成目标账号，然后让这台机器从网卡启动。机器启动后读自己的序列号，对上表格里的那一行，按指定系统无人值守安装。密码只保存在小主机的数据目录里，页面不显示。

IPMI 通道按通道 1 处理。BMC 要能从装机网拿到小主机发出的地址，小主机才能按 MAC 找到它。

## 登录

控制台要先登录。目标机取启动文件用的 `/boot/` 不需要登录。

第一次启动时自动建一个管理员 `admin`，随机密码写在 `data/auth/initial-admin-password`。登录后在「我的账号」里改掉密码，然后删除这个文件。

三种登录方式，权限相同：

- **密码**：用户名加密码。
- **访问密钥**：在「我的账号」里生成，形如 `pxe_...`，只显示一次。可以贴在登录页登录，也可以给脚本用：`curl -H "Authorization: Bearer pxe_..." http://控制台/api/projects`。
- **SSH 公钥**：在「我的账号」里添加 `~/.ssh/id_ed25519.pub`。登录页填用户名，点「获取挑战码」，在自己电脑上执行页面给出的 `ssh-keygen -Y sign` 命令，把输出的签名贴回去。需要 OpenSSH 8.2 以上，Windows 10 自带的也可以。

角色分两种。管理员可以在「用户」页新建、停用、删除用户，重设密码，管理所有人的密钥。普通用户能用装机、项目和批量任务，只能管理自己的密码和密钥。改密码、停用、改角色或删掉某把密钥后，相关的登录立即失效。

忘记密码时在小主机上执行，会打印新的随机密码，并把这个用户设为启用的管理员：

```bash
docker compose exec console node --experimental-strip-types scripts/auth-admin.ts reset-password admin
```

账号存在 `data/auth/users.json`，密码用 scrypt 存哈希，访问密钥只存哈希。会话签名用的密钥是 `data/auth/secret`，删掉它所有人都要重新登录。

## 远程控制台

服务器列表里点「远程控制台」，新窗口打开那台服务器的 BMC 网页，已经自动登录，可以看屏幕、用键盘鼠标、挂虚拟光驱。浏览器只连小主机，不需要能直接访问装机网上的 BMC。

- 走 HTTPS 443 端口。证书是 nginx 镜像构建时生成的自签证书，第一次打开要在浏览器里点「继续访问」。
- BMC 的账号密码留在小主机上：登录请求经过小主机时，换成服务器表里的账号（改过账号用目标账号，不行再用原账号），浏览器拿不到密码。
- 链接 60 秒内有效、只能用一次；打开后 12 小时有效。控制台用户被停用或改了密码，远程控制台也随之断开。
- 一个浏览器同时只能看一台。打开另一台时，前一台的窗口会失效。
- 已在 AMI MegaRAC（技嘉）上验证。其他品牌的 BMC 网页也会转发，但自动登录只认 AMI 的登录页，别的品牌需要手动输入账号。

## 接线

1. 小主机装 Ubuntu 或 Debian，安装 Docker 和 Compose 插件。
2. 装机网口（默认 `eth1`）接到一台交换机。目标服务器的 PXE 网口也接到这台交换机。
3. 给装机网口配上控制台里的地址，默认是 `192.168.77.1/24`。不要让办公室的路由器也在这张网上发 DHCP。

```bash
sudo ip addr add 192.168.77.1/24 dev eth1
sudo ip link set eth1 up
```

## 启动

```bash
./scripts/fetch-ipxe.sh
docker compose up -d --build
```

控制台是 [http://127.0.0.1:43123](http://127.0.0.1:43123)。目标机通过 80 端口取内核、ISO 和应答文件。

改过装机网口或地址池之后，执行：

```bash
docker compose restart dnsmasq
```

本机只看界面、不启动 DHCP 时：

```bash
cd console
npm install
npm run dev
```

开发服务器同样监听 43123，数据写在仓库的 `data/`。

## 导入镜像

在「镜像」页上传 ISO。上传按 4MB 一段进行，网络抖动会自动重试；中断后重新选择同一个文件会从断开的位置继续，没传完的上传会列在页面上，可以放弃。控制台用 `xorriso` 识别家族并抽出内核。镜像列表显示名称、系统版本和大小。

支持：

| 家族 | 应答 | 安装源 |
| --- | --- | --- |
| Ubuntu | autoinstall | ISO 本身 |
| Debian | preseed | 展开后的安装树 |
| Rocky Linux / AlmaLinux | kickstart | 展开后的安装树 |

然后在「安装配置」里写主机名、用户、密码和磁盘策略。主机名可以用 `srv-{{mac_last4}}`。磁盘策略会清空所选磁盘，菜单文案会标明这一点。

## 装完后批量管理

装机时，安装后脚本会把小主机的 SSH 公钥写进目标机 root 的 `authorized_keys`。私钥在 `data/ssh/`，第一次用到时生成。

在项目的服务器列表里勾选机器，下方的「批量任务」以 root 身份用 bash 对它们执行同一段脚本：

- 地址按这个顺序找：服务器表里的系统地址、和小主机同网段的网卡规划、机器的固定 IP、装机网的 DHCP 租约、需要走路由的网卡规划。列表的「系统地址」列显示每台会用哪个地址。
- 驱动包等文件先上传，执行前用 scp 推到每台机器的临时目录。脚本里用 `$PXE_FILES` 访问，执行完自动删除。`$PXE_SN` 是这台的序列号。
- 可以设置同时执行的台数和单台超时。每台的退出码和输出单独记录，没成功的可以一键重选再跑。
- 交付前点「撤掉控制台公钥」，从机器上删掉小主机的公钥，之后就不能再从这里登录这些机器。

这个功能上线前装好的机器没有公钥，不能批量管理。

## 现场确认

1. 打开控制台，确认 UEFI 和 BIOS 固件都是「已就位」。
2. 目标机从网卡启动，应看到「PXE 装机台」菜单，超时后回到本地硬盘。
3. 需要装机时，上传服务器表并打开项目开关；序列号对不上的机器可以在启动菜单里手动选安装项。

## 目录

- `console/`：控制台和应答、菜单生成
- `deploy/`：dnsmasq 与 nginx
- `data/`：ISO、租约、SSH 密钥、批量任务记录和上传的文件。不进 Git
