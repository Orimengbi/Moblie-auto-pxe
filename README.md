# 资产运维平台

服务器资产台账和运维，PXE 装机是其中一项功能。跑在一台 x86_64 移动小主机上：管理口打开控制台，装机网口给目标服务器提供 DHCP、TFTP 和启动菜单。

- **资产**：每台设备一条记录，序列号唯一。记编号、类型、厂商型号、归属客户、负责人、位置、生命周期状态、BMC、系统地址、采购和保修。点一行看硬件配置、变更、接口、GPU/网卡拓扑、光模块和操作记录。
- **装机批次**：一次装机用的安装设置、DHCP 地址池和服务器表。表里的机器自动入库，已经入库的按序列号挂上去；装机过程中找到的 BMC 地址、改过的账号、系统地址会同步到资产。
- 菜单里自选 Ubuntu、Debian、Rocky Linux 或 AlmaLinux，按配置无人值守安装。表里没有的机器、已经装好的机器，菜单超时后从本地硬盘启动，避免误装机。要重装时在批次里点「重装」。

管理口不要接到装机交换机上。DHCP 只监听配置里的装机网口。

## 资产

「资产」页列出所有设备，可以按状态、归属客户、机房、类型筛选，搜编号、序列号、型号、IP。勾选后可以批量改状态、改归属、电源和引导、执行批量任务。

- **生命周期**：入库 → 上架 → 装机中 → 待交付 → 在用 → 维修中 → 下架 → 报废。装机批次开始装这台时变成「装机中」，装好后变成「待交付」，其余手动改。每次变化都记进这台的「记录」。
- **编号**：按「设置」里的编号规则生成，例如 `RS-{type}-{seq:5}` 得到 `RS-SRV-00001`。可用 `{type}` 类型代码、`{customer}` 客户代码、`{seq}` 入库顺序号（`{seq:5}` 补零到 5 位）、`{year}` 入库年份、`{sn}` 序列号。改规则或客户代码后所有编号马上按新规则显示；单台可以手动指定编号，不受规则影响。
- **机房和机柜**：「机房」页按机房显示机柜，同一机房的机柜并排，U1 在最底下。资产记在哪个机柜、从第几个 U 起、占几个 U；0U 是侧挂（竖装 PDU 等），不占 U 位。同一机柜里 U 位不能重叠，也不能超出机柜高度。点空 U 位能直接把一台资产放进去，还在「入库」的资产放进机柜后自动改成「上架」。机柜可以按前缀加编号一次建一排（A01…A20）；改矮时不能低于已经放着的设备，有设备的机柜、有机柜的机房不能删。
- **客户**：资产归属哪个客户，没有归属的算自有。客户代码用在编号里。
- **采购和保修**：供应商、采购单号、日期、价格，保修方、服务级别、起止日期。总览页列出已过保和 90 天内到期的在用资产。
- **BMC 账号**：主账号被拒时再试备用账号。装机批次改过 BMC 账号后，资产上的主账号换成目标账号，原账号做备用。电源、远程控制台、BMC 采集都用资产上的账号。

资产、客户、审计存在 `data/pxe.db`（SQLite，Node 自带的 node:sqlite）。硬件采集记录、收发光读数还是放在 `data/inventory/<资产 id>/`、`data/optics/`。从装机批次里删掉一台不删资产和它的硬件记录；删资产（只有管理员能删）才一起删。

**Excel 批量导入**：「资产」页的「Excel 导入」。一行一台，按序列号对上：已经有的只改填了的格子，空格子不动；没有的入库。先预览会新建、更新哪些和哪几行有问题，确认后才写入，有问题的行跳过。归属客户写客户代码或名称，写「自有」清空；机柜写机柜号（多个机房有同名机柜时在「机房」列写机房代码），写「无」移出机柜。客户和机柜要先建好。「导出 Excel」导出的表（不带密码）改完可以原样导回来。

## 监控和告警

控制台每 30 秒看一次哪些资产到了检查时间（默认只查「在用、维修中、待交付」的），同时最多查 4 台。间隔、范围、阈值在「设置 → 监控」里改，管理员才能改。

- **BMC**（默认每 5 分钟）：用 ipmitool 读传感器（`sdr elist`）和事件日志（`sel elist`）。传感器状态是 cr/nr 或读数里有「Failure detected」「AC lost」等算严重，nc 算警告；SEL 里新出现的严重、警告事件开告警，第一次检查只记下位置，不报以前的。传感器表缓存在 `data/monitor/<资产 id>.sdr`，读一遍从几十秒降到几秒。BMC 连续两次（可改）连不上报「BMC 连不上」。
- **系统内**（默认每 30 分钟，0 关闭）：用控制台的 SSH 密钥登录系统地址，nvidia-smi 看到的 GPU 比最近一次硬件采集少就报「GPU 少了 N 张」（掉卡），nvidia-smi 报错、温度超线、不可纠正 ECC、内核日志里的 Xid（79、48、74、94/95 等算严重）、硬盘 SMART 不通过都会报。
- **告警**：同一台同一个问题没恢复前只有一条。传感器、BMC 连不上、GPU、硬盘这类状态告警，条件消失就自动恢复；BMC 事件和 Xid 不会自己恢复，要点「处理完」。可以「确认」（表示有人在看），可以「转工单」（严重的按高优先级建故障单，资产转维修中）。告警开和恢复都记进资产时间线。
- 「告警」页列出所有告警；资产侧边栏的「监控」页看这台的告警、传感器、最近的 BMC 事件、GPU 和硬盘，可以「立即检查」。告警目前只在页面上显示，没有推送。

## 工单和备件

**工单**（「工单」页，或资产侧边栏的「工单」）：编号 `WO-年份-序号`，有类型（故障、维修、变更、其他）、优先级、负责人、厂商工单号、描述和处理记录。状态是待处理 → 处理中 → 等待中（等备件、等厂商）→ 已解决 → 已关闭，解决后可以重新打开。

- 故障和维修单默认把资产转成「维修中」，记下原来的状态；这台的这类单子都解决或关闭后自动改回去，重新打开再转回维修中。
- **换件**在工单详情里登记：旧件可以从这台最近一次硬件采集里挑，也可以手填，标成待返修、已拆下或报废，库里没有这件就自动登记一件；新件从在库的同类备件里挑，或者直接填序列号。换件同时记进工单、资产时间线和备件流转记录。

**备件**（「备件」页）：每件一条，状态是在库、已装机、已拆下、待返修、返修中、报废。上面按类型和型号汇总在库数量。

- 入库一次一个型号，序列号一行一个（可以从 Excel 整列贴），没有序列号的按数量入；有一个号已经在库里，整批不入。
- 硬件采集比出某个部件换了序列号时，记进资产时间线；新序列号是库里的备件就自动标成装在这台上，原来登记装在这台上、这次不见了的标成「已拆下」。
- 删资产时，登记在它上面的备件改成「已拆下」，留在库里。

## 操作审计

「审计」页（管理员）记录谁在什么时间、从哪个地址做了什么：登录和登录失败、资产、客户、机房机柜、工单、备件的改动、装机批次的改动和上传、电源和引导、打开远程控制台、批量任务（脚本内容记前 1500 个字）、镜像和安装设置、用户管理。只增不改。单台资产的操作也显示在它侧边栏的「记录」里。

## 装机批次和服务器表

新建装机批次后，在里面写安装设置、DHCP，上传服务器表。

打开一个批次的开关后，装机使用这一套临时地址池和安装菜单。同时只能打开一个批次。没有打开的批次时，不分配装机地址。DHCP 地址池要和这台小主机某一块网口在同一个子网。多块网口时，不必跟打开控制台的那个地址相同。DNS 和 VLAN 可以不填。

批次开始时上传一张服务器表，一行一台机器。列是：序列号、IPMI MAC、原用户、原密码、目标用户、目标密码、IPMI 地址、掩码、路由、IPMI VLAN、安装系统、系统地址、系统掩码、系统网关、系统DNS、系统网卡、定制需求。VLAN 和系统那几列可以留空。

系统地址填了，装机最后一步就把它配成业务网卡的静态 IP（netplan、NetworkManager 或 /etc/network/interfaces，看系统用哪个），PXE 口保持 DHCP 不动；没填就不改系统网络。掩码必填，可以写 255.255.255.0、24，或者直接把地址写成 10.50.0.11/24；网关、DNS 可以留空，DNS 多个用逗号分开。系统网卡填接口名（如 ens1f0）或 MAC；留空时自动挑一块不是 PXE 口的物理网卡，先挑插着线的。整盘镜像的内存运行也会配上并立即生效。安装系统要和该批次里某条安装设置的名称一致。定制需求会附加到那台机器的安装后脚本。

上传并且批次开关打开之后，小主机用 DHCP 租约按 IPMI MAC 找到 BMC，按表里的地址、掩码、路由和 VLAN 写入 IPMI 网络，再把用户和密码改成目标账号，然后让这台机器从网卡启动。机器启动后读自己的序列号，对上表格里的那一行，按指定系统无人值守安装。密码只保存在小主机的数据目录里，页面不显示。

IPMI 通道按通道 1 处理。BMC 要能从装机网拿到小主机发出的地址，小主机才能按 MAC 找到它。

## 登录

控制台要先登录。目标机取启动文件用的 `/boot/` 不需要登录。

第一次启动时自动建一个管理员 `admin`，随机密码写在 `data/auth/initial-admin-password`。登录后在「我的账号」里改掉密码，然后删除这个文件。

三种登录方式，权限相同：

- **密码**：用户名加密码。
- **访问密钥**：在「我的账号」里生成，形如 `pxe_...`，只显示一次。可以贴在登录页登录，也可以给脚本用：`curl -H "Authorization: Bearer pxe_..." http://控制台/api/projects`。
- **SSH 公钥**：在「我的账号」里添加 `~/.ssh/id_ed25519.pub`。登录页填用户名，点「获取挑战码」，在自己电脑上执行页面给出的 `ssh-keygen -Y sign` 命令，把输出的签名贴回去。需要 OpenSSH 8.2 以上，Windows 10 自带的也可以。

角色分两种。管理员可以在「用户」页新建、停用、删除用户，重设密码，管理所有人的密钥。普通用户能用资产、装机批次和批量任务，只能管理自己的密码和密钥。改密码、停用、改角色或删掉某把密钥后，相关的登录立即失效。

忘记密码时在小主机上执行，会打印新的随机密码，并把这个用户设为启用的管理员：

```bash
docker compose exec console node --experimental-strip-types scripts/auth-admin.ts reset-password admin
```

账号存在 `data/auth/users.json`，密码用 scrypt 存哈希，访问密钥只存哈希。会话签名用的密钥是 `data/auth/secret`，删掉它所有人都要重新登录。

## 远程控制台

服务器列表里点「远程控制台」，在控制台页面里直接打开那台服务器的 KVM 画面，可以看屏幕、用键盘鼠标、挂虚拟光驱，不另开窗口。浏览器只连小主机，不需要能直接访问装机网上的 BMC。

- 和控制台走同一个地址和端口（路径 `/__bmc/`），控制台登录后就能用，不用另外开端口。
- BMC 的账号密码和网页会话都留在小主机上，由小主机登录 BMC（改过账号用目标账号，不行再用原账号），浏览器拿不到。
- 控制台用户被停用或改了密码，远程控制台随之断开。点「关闭」就断开 KVM。
- 目前适配 AMI MegaRAC 的 H5Viewer（技嘉等）。BMC 的 KVM 会话数有上限（这台是 2 个）。

## 接线

1. 小主机装 Ubuntu 或 Debian，安装 Docker 和 Compose 插件。
2. 装机网口（默认 `eth1`）接到一台交换机。目标服务器的 PXE 网口也接到这台交换机。
3. 给装机网口配上控制台里的地址，默认是 `192.168.77.1/24`。不要让办公室的路由器也在这张网上发 DHCP。

```bash
sudo ip addr add 192.168.77.1/24 dev eth1
sudo ip link set eth1 up
```

## 启动

```bash
./scripts/fetch-ipxe.sh
docker compose up -d --build
```

控制台是 [http://127.0.0.1:43123](http://127.0.0.1:43123)。目标机通过 80 端口取内核、ISO 和应答文件。

改过装机网口或地址池之后，执行：

```bash
docker compose restart dnsmasq
```

本机只看界面、不启动 DHCP 时：

```bash
cd console
npm install
npm run dev
```

开发服务器同样监听 43123，数据写在仓库的 `data/`。

## 导入镜像

在「镜像」页上传 ISO。上传按 4MB 一段进行，网络抖动会自动重试；中断后重新选择同一个文件会从断开的位置继续，没传完的上传会列在页面上，可以放弃。控制台用 `xorriso` 识别家族并抽出内核。镜像列表显示名称、系统版本和大小。

支持：

| 家族 | 应答 | 安装源 |
| --- | --- | --- |
| Ubuntu | autoinstall | ISO 本身 |
| Debian | preseed | 展开后的安装树 |
| Rocky Linux / AlmaLinux | kickstart | 展开后的安装树 |

然后在「安装配置」里写主机名、用户、密码和磁盘策略。主机名可以用 `srv-{{mac_last4}}`。磁盘策略会清空所选磁盘，菜单文案会标明这一点。

### 整盘镜像

也可以导入用 dd 从装好的机器上导出的整盘镜像（`.img`，或者内容是整盘的 `.iso`，都可以压缩）。要求：GPT 分区表、Ubuntu 或 Debian、根分区是 ext4 且是最后一个分区，initrd 由 initramfs-tools 生成。导出时只要导到根分区结束为止，不用导整块盘。

导入时控制台把镜像拆成 `head.img.zst`（分区表和 EFI 分区）和 `root.img.zst`（收缩到最小的根分区），取出镜像自带的内核和 initrd，再生成一个追加的 `pxeimg.cpio`。原文件转完就删。

用它建的安装配置在启动菜单里有两项：

- **写盘**（Install 下面）：根分区下载进内存把系统跑起来，再按磁盘策略选盘，清空后写入镜像，把根分区扩到整块盘，在新系统里设主机名、账号、控制台公钥、IPMI 和网卡，执行安装后脚本，标记已安装后重启。
- **内存运行**（Run in RAM 下面）：不碰硬盘，系统整个在内存里跑，写入控制台公钥后可以用批量任务管理。关机后什么都不留。

安装配置里的“启动方式”决定绑定这条配置的机器（服务器表里的安装系统、或机器页里绑定安装）菜单超时后走哪一项：落盘部署走写盘，内存运行走内存运行。选内存运行时机器不会被标记为已安装，每次从网卡启动都重新进内存系统；要让不同机器用不同方式，就给同一个镜像建两条配置。菜单里两项都能手动选。

两种方式都要求目标机内存比收缩后的根分区大（根分区大小在抽取日志里）。整盘镜像不能用自定义分区，软件包、语言和时区也不生效，用镜像里原有的。镜像里已经有账号的，配置里用户名留空就不动镜像里的账号和密码；只填用户名不填密码，会保证这个用户存在并加进 sudo 组，但不改它的密码。

## 装完后批量管理

装机时，安装后脚本会把小主机的 SSH 公钥写进目标机 root 的 `authorized_keys`。私钥在 `data/ssh/`，第一次用到时生成。

在资产列表或装机批次的服务器列表里勾选机器，下方的「批量任务」以 root 身份用 bash 对它们执行同一段脚本：

- 地址按这个顺序找：和小主机同网段的系统地址或网卡规划、机器的固定 IP、装机网的 DHCP 租约（系统地址在业务网卡上时 PXE 口还是 DHCP）、需要走路由的系统地址或网卡规划。列表的「系统地址」列显示每台会用哪个地址。
- 驱动包等文件先上传，执行前用 scp 推到每台机器的临时目录。脚本里用 `$PXE_FILES` 访问，执行完自动删除。`$PXE_SN` 是这台的序列号。
- 可以设置同时执行的台数和单台超时。每台的退出码和输出单独记录，没成功的可以一键重选再跑。
- 交付前点「撤掉控制台公钥」，从机器上删掉小主机的公钥，之后就不能再从这里登录这些机器。

这个功能上线前装好的机器没有公钥，不能批量管理。

## 硬件配置

在服务器侧边栏的「硬件配置」里点「采集硬件配置」，读这台机器的整机型号和序列号、主板、CPU、内存、硬盘、GPU、网卡、电源和固件版本，每个部件记槽位、型号、厂商、序列号、固件，以及各自的属性：CPU 的核数、线程、频率，内存的容量、类型、速率、Rank，硬盘的容量和介质，GPU 的显存，网卡的 MAC、速率和料号等。采集作为一条任务记在「最近的任务」里，跑完侧边栏自动刷新。

两种来源，可以只选一种：

- **系统内（SSH）**：用控制台公钥登录系统，执行 `dmidecode`、`lsblk`、`smartctl`、`nvidia-smi`、`ethtool`、`lspci`（网卡序列号从 PCI VPD 读）。信息最全，要求系统开着、写过控制台公钥；没装的工具会跳过并在结果里提示。内存运行的整盘镜像也可以采。
- **BMC（Redfish）**：用服务器表里的 IPMI 账号读 BMC，不需要系统，关机也能读，还能读到电源和 CPLD、Retimer 这类固件。字段多少看 BMC：有的 BMC 只报电源在不在位，没有型号和序列号。带 GPU 底板的机器 Redfish 文档很多，一台要一两分钟。

两边的槽位名写法不同（比如 GPU 一边是 PCI 地址、一边是 GPU_0），所以各自存、各自比。每台机器每个来源保留最近 30 次。每次采集都和上一次同来源的结果比：同一槽位序列号变了算「更换」，型号、固件、容量等变了算「变化」，还有「新增」「拆除」。盘符、网口名重排不算变化。

服务器列表的「硬件」一列显示有没有采集、是否符合基准、最近一次的变化数。点列表里的一行，右边滑出这台机器的侧边栏：「硬件配置」看明细、基准检查和历史上某一次的配置，「变更记录」按时间列出每次采集比出的变化，可以按来源筛、只看有变化的。

侧边栏的「接口」列出硬盘位、PCIe 插槽和网口有没有在用，跟着硬件采集一起读，可以只看空闲的。系统内：PCIe 插槽和 M.2 槽按 BIOS 的插槽表（`dmidecode -t 9`）列，再按总线地址找插着的设备，BIOS 报空闲但找到了设备的按占用算；盘位来自背板的 SES（`/sys/class/enclosure`）、板载 SATA 口和 PCIe 热插拔槽（装着 NVMe 的算盘位；同一批热插拔槽里有 NVMe 时，空槽也按 NVMe 盘位算），对不上盘位的盘（直连、RAID 卡后面的等）单独列出；背板不报 SES 的机器看不到空盘位。网口不判断占用，链路、速率、IP 和所属 bond 都列出来，IB 模式没有网口名的口按 RDMA 设备列。BMC：Chassis 的 PCIeSlots、Storage 里的盘位（有的 BMC 会列空盘位）和网卡的 Ports，各家 BMC 给的多少不一。这个功能上线前的采集没有接口数据，要重新采一次。

侧边栏的「GPU / 网卡拓扑」画出 NUMA 节点 → 根复合体 → PCIe 交换芯片 → GPU 和网卡的树，下面是 GPU 到 GPU、GPU 到每张网卡的连接矩阵（NV#、PIX、PXB、PHB、NODE、SYS，和 `nvidia-smi topo -m` 的叫法一样）。PCIe 关系按 sysfs 里每个设备的上游路径算，没有 GPU 的机器也能看网卡之间的关系，`nvidia-smi` 不列的网卡也在里面；NVLink 条数取自 `nvidia-smi topo -m`。拓扑只有系统内采集才有，这个功能上线前的采集要重新采一次。

光模块的型号、厂商、序列号、固件、规格和波长在系统内采集时一起记进硬件明细（类别「光模块」，按序列号一个模块一条，twin-port 模块接的两个口都记在这一条的槽位里），也参与变化比对和基准检查。NVIDIA/Mellanox 网卡用 `mlxlink` 读（系统里要有 MFT 或 mstflint 带的 mlxlink，CMIS 的 OSFP/QSFP-DD 也能解），其他网卡用 `ethtool -m`；旧版 ethtool 解不了 CMIS 模块，只会提示读不到。

收发光强度要手动查：侧边栏的「光模块」里点「查询收发光」，SSH 进系统读，一个模块一行，每个口每条 lane 的发光、收光（dBm）分行列出，还有温度和电压，按模块自己报的告警门限标色：红色超出门限，黄色离下限不到 2 dB。二十来个口要十几秒，只留最近一次读数。有的模块固件只报整数 dBm。

**基准配置**：在一台确认没问题的机器的硬件明细里点「设为批次基准」，按类别和型号（内存、硬盘再加容量）数个数；同一组里过半一致的固件版本记为要求，所以基准机自己有一张卡固件不一样也会被标出来。生成后在批次的「基准配置」里改数量、清掉不想检查的固件要求、删条目或手动加条目。检查时报缺件、多件、基准里没有的型号和固件不一致；基准里没有的类别不检查。基准按生成它的那个来源比。

## 现场确认

1. 打开控制台，确认 UEFI 和 BIOS 固件都是「已就位」。
2. 目标机从网卡启动，应看到「PXE 装机台」菜单，超时后回到本地硬盘。
3. 需要装机时，上传服务器表并打开批次开关；序列号对不上的机器可以在启动菜单里手动选安装项。
